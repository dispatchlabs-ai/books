Asset type: Books product screen design, one desktop and one mobile viewport on a single landscape board.
Style: high-fidelity calm financial workspace, white and very light cool gray surfaces, navy text, restrained blue primary controls, green confirmed states and amber exceptions; crisp sans-serif, strong typography, fine dividers, generous spacing, modest corner radius. Continuity with existing Books cash-flow concept. No decorative illustrations or device hardware.
Composition: large landscape board roughly 2400x1400. One complete desktop app viewport on left (about 76% width) and one full-height mobile app viewport on right (about 23% width), small gap. Label Desktop and Mobile outside viewports. Desktop compact fixed sidebar Books, entity switcher, Overview, Accounts, Activity, Journals, Imports, Reconcile, Reports, Settings; highlight relevant navigation. Mobile uses compact header with entity context and 4-item bottom navigation Home, Activity, Accounts, More, drilldown back header for forms. Mobile reflows information and retains meaningful actions, never miniaturizes desktop. Both viewports must show the specified SAME page and dominant state. Do not add other pages except requested state sheet. Make UI text legible and real, not gibberish. Avoid excessive microcopy. Footer outside app: Design concept · Synthetic data.
Constraints: This is an unbuilt UI concept over existing Books API. Use invented Maple Household / Example Studio names and synthetic values only. No personal identifiers, credentials or private balances. Distinguish source evidence, drafts and posted ledger; no unimplemented bank sync, invoicing, payment execution, payroll, AI autopost controls or forecast unless explicitly marked planned. Do not show API method names or raw JSON to ordinary users. No perspective, shadows behind device mockups, photos, gradients or marketing copy.
